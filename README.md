# 单词弹幕

背单词最烦的不是记不住，是"打开 App 背单词"这个动作本身。我的想法很朴素：单词能不能自己飘过来，我扫一眼就行。

所以有了这个东西。Windows 桌面上的一个小程序，屏幕最上面一条带子里不断飘过英文单词、词性和中文释义。它不抢焦点、不挡鼠标，我写代码或者看视频的时候余光扫一眼。

动手前给自己定了两条死规矩：

- **不装第三方库**。`tkinter` + `ctypes` 就是全部，Python 装好就能跑，不用 pip。
- **不能卡**。飘字的东西一卡观感立刻崩，这条比功能本身重要。

前前后后写了一阵，主程序就一个 `danmaku.py`。注释占了很大一块，原因最后说。

## 跑起来

需要 Windows + Python 3.11 以上，没有别的依赖。

双击 **`启动单词弹幕.bat`**，弹幕会立刻开始，控制面板自动收起，只在屏幕右下角留一个小番茄。单击番茄唤回面板，按住可以把番茄拖到顺手的位置（位置会记住）。

想停：`停止弹幕.bat`，或者按 `Ctrl+Alt+Q`。想开机自启：跑一次 `开机自启设置.bat`，把弹幕的快捷方式拖进弹出的文件夹。

出了事想看清楚，就用带控制台的方式跑：

```
python danmaku.py --run
```

## 用起来是什么感觉

默认每 2.5 秒从右边进来一条，同屏最多 5 条，速度大概 9 秒横穿屏幕。纵向是屏幕上方 15% 高的一条带子，里面分成 3 条轨道。

这里有个我挺满意的设计：**轨道不是"这行有词就不能再用"**，而是判断"新来的这条放进去会不会撞上"。所有弹幕同速左移，所以只要入场那一刻不重叠，之后就永远不会重叠 —— 于是最右边经常能连着排好几条，出词节奏稳得多（按旧规则，三条轨道一占满就开始丢拍）。唯一的例外是被鼠标停住的那条：它不动，所以悬停期间整行算占用。

一条弹幕的内容是「单词 + 词性 + 释义」，默认只取前 2 个义项、最多 2 个词性（面板上可调）。太长的会按分号截断，再长就整体砍到屏宽的 78% 以内 —— 否则一条横穿整屏，谁也看不清。

### 大写锁定键

平时弹幕是**鼠标穿透**的，点不到、也挡不住你。按一下 CapsLock（把指示灯点亮），弹幕就被"接住"了：

- 鼠标悬到哪条，哪条就**原地停住**，外面浮出一个半透明的圆角灰框；
- 框里显示音标，右边三个图标：🔊 读音、🔍 查词、★ 收藏；
- 点 🔊 播这个词的读音（mp3 在 `audio\`，没有就静音）；点 🔍 用默认浏览器开这个词的有道词典页面；点 ★ 收进收藏夹；
- 🔊 和 🔍 点下去会**闪一下黄色**，告诉你这一下点到了；
- 鼠标移开后它不会立刻走，而是**自己加速往左拉开距离**，压着它的那几条原地停一步让路。如果有人正好压在它左边（往左走只会追得更深），才退回排队等，8 秒兜底。

再按一下 CapsLock 就恢复穿透。

### 收藏夹

点 ★ 收藏的词会写进 `books` 下的 `已收藏单词.csv`，格式和其它词书**完全一样**（UTF-8 BOM、CRLF、按字母序）。所以它能直接在面板的词书下拉里选中 —— "只弹我收藏的词"不需要任何单独的功能，换本书而已。这是整份代码里我最喜欢的一处。

## 踩过的坑

留几个印象最深的，省得以后（或者别人）再踩一遍。

**1. 帧率：瓶颈不在"移动"，在"画字"。**

一开始同屏 5 条只有 58fps，帧间隔 p95 能到 34ms。查下来每帧开销几乎全在 Tk 重新光栅化 text item 上：一条弹幕是 9 个 item（8 向描边 + 正文），5 条就是 45 个。

解法是：每条弹幕**出场那一刻**用 GDI 把整条画成一张位图（描边一起画进去），之后每帧只 blit 一张图。同屏条数就这样从帧率公式里消失了，现在同屏 8 条也在 100fps 以上。

中间还有个坑：位图我一开始输出 PPM，快是快，但 PPM **没有"透明色"这个概念**。悬停那条会被提到灰框上面，整块框就被位图盖住；Windows 再按窗口色键把底图抠掉 —— 抠出来的是**桌面**而不是框，看起来就是"文字笔画之间全是白底"。换成带 `tRNS` 的 PNG 之后，Tk 在 canvas 合成阶段就把这些像素当 alpha=0 处理，透出来才是下面那块框。

**2. `-transparentcolor` 在 Windows 上不生效。**

tkinter 自带的透明色属性实测会把窗口糊成一块实心黑底。最后只能纯 ctypes：`SetLayeredWindowAttributes` 上色键，`WS_EX_LAYERED | WS_EX_TRANSPARENT` 做穿透。坑在于 `COLORREF` 是 `0x00BBGGRR` 而不是 RGB，写反了色键就对不上。

顺带一提，弹幕窗口**只有弹幕带那么高**，不是整屏 —— 整屏 layered 窗口每帧要重新合成三千多乘两千个像素，掉帧就是这么来的。

**3. 悬停的命中检测不能用鼠标事件。**

窗口是色键抠洞的，被抠掉的像素鼠标会直接"漏"过去，洞口边缘的 crossing 事件时有时无，`<Motion>` 完全靠不住。改成每 90ms 主动读一次真实光标坐标、减去窗口原点，跟事件派发彻底脱钩，掉帧或者鼠标不动都不会漏判。

同一条规矩还有个不那么直觉的后果：**图标要画成实心的**。🔍 的镜面如果只描一圈边、中间空着，那块空的就是被抠掉的像素，鼠标点上去穿过去落到桌面 —— 命中框算得再准也没用，因为那个位置根本没有窗口。逐个像素量过：镜面里画过颜色的像素（34,34,34）全都点得中，漏出桌面的（0,0,0）一个都点不中，一一对应。所以镜面是拿底色填实的，看着是镂空，其实是实心的。

**4. 判断 CapsLock 开关别用错 API。**

`GetAsyncKeyState(VK_CAPITAL) & 1` 那个低位是"自上次查询之后按下过"的**易失位**：按下去立刻读是 1，半秒后再读就变 0（被自己上一次查询吃掉了）。拿它当开关的效果是"按一下亮一瞬"，用起来像必须一直按住。真值是 `GetKeyState(VK_CAPITAL) & 1`。

**5. 热键得是系统级的。**

面板收起来之后，程序自己已经没有键盘焦点了，Tk 的 `bind_all` 那套整个哑掉 —— 而我一直以为 `Ctrl+Alt+Q` 是能用的。现在改成 `RegisterHotKey`，单开一根线程收 `WM_HOTKEY`，再把动作丢回主线程执行（Tcl 不是线程安全的，子线程里碰 Tk 会随机炸）。某个组合被别的软件占了才退回 Tk 绑定。

**6. 数据里"两个空格"是有意义的。**

词书的 `mean_cn` 列用**两个空格**分隔不同词性（`v. 请求；上诉；  n. 呼吁`），这是词性块的分隔符。这个坑真踩到了：`acquire` 那条数据词性后面正好跟了两个空格（`v.  （通过努力、能力）获得…`），于是 `v.` 被切出去当成一个义项，弹幕上显示成 `acquire  v.；获得`。四本词书里那一份数据全中。

后来写了个体检脚本把整库扫一遍才发现 —— 这种事肉眼看弹幕是发现不了的，你只会觉得"个别词怪怪的"。

**7. config.json 写坏过一次。**

有次设置莫名其妙回到默认，一看 `config.json` 是 0 字节：写配置是直接 `open(w)` 覆盖，中途被杀就留半截文件，而读取那边的异常被 `except: pass` 静默吃掉了。现在写配置先写 `.tmp` 再 `os.replace`（收藏夹一直这么干，配置反而漏了），坏文件也会往 `error.log` 记一行，不再无声无息。

**8. 微软雅黑其实缺 IPA 字符。**

音标一直用雅黑渲染，我以为它什么都有。直到用 `GetGlyphIndicesW` 量了一遍：`ə ɜ ɪ ʊ ˈ ː` 全是"无字形"，能显示出来纯粹是 Windows 的 font linking 在逐字兜底。想不依赖它，把 `PHON_FACE_FALLBACK` 填成 `Segoe UI` 就整行换过去。

**9. 快捷方式图标变成一张白纸。**

图标文件一点问题都没有（7 档尺寸都能正常渲染），问题在**项目目录被盖上了「低完整性」标记** —— 在这个目录里跑过带沙箱的工具就会这样。桌面上其它快捷方式引用的 `.ico` 全在 `%APPDATA%` / `%LOCALAPPDATA%`，那些是正常的「中」完整性，只有项目里这一份是「低」。

Explorer 自己在「中」完整性下跑，而 Windows 不允许它从低完整性的文件里读图标和缩略图 —— 跟"从网上下载的文件不给预览"是同一条规矩。于是快捷方式只能退回去显示通用白纸图标，重做一遍也没用（文件还是低完整性）。

所以 `创建桌面快捷方式.bat` 现在会先把 ico 复制到 `%LOCALAPPDATA%\单词弹幕\` 再让快捷方式指过去。程序本身不用这个 ico（窗口和把手用的是 `logo` 下的 png），复制出去不影响别的地方。

## 参数

面板上的改动**全部实时生效**，并且自动存进 `config.json`：

- 速度、出现间隔、顶部区域高度、字号、不透明度
- 同屏条数上限（1–8）、释义条数、最多词性数
- 出现区域：屏幕上方 / 中部 / 下方 / 随机
- 随机颜色（关掉就统一白色）
- 词书、字体

面板可以拖边框自由缩放，拖小了右边会出现滚动条，鼠标滚轮也能翻。底部一个「恢复默认」（把手位置不动 —— 那是窗口摆哪儿，属于位置不属设置），一个「来一条」（同屏满了就顶掉最老的那条，保证点了有反应）。

滑块把手是一颗自己画的小番茄，平时藏着，鼠标上去才弹出来。为什么画而不是直接用 🍅 字符：Tk 8.6 不支持彩色 emoji，写上去只会得到一颗单色轮廓。

## 词书

`books` 下每个 `.csv` 就是一本词书，面板里切换。自带四本（都从百词斩全量词库导出：六级 6203 / 六级核心 2551 / 四级 4439 / 四级高频 739），外加程序自己写的收藏夹。

只有三列：`word,accent,mean_cn`。想加书就按同样格式丢个 csv 进去重启。

> ⚠️ `mean_cn` 里词性之间那**两个空格**是分隔符，别顺手压成一个。

## 目录

```
danmaku.py            主程序，单文件（tkinter + ctypes，零第三方依赖）
启动单词弹幕.bat       双击启动，无黑框
停止弹幕.bat           一键停掉
创建桌面快捷方式.bat   生成带番茄图标的快捷方式
开机自启设置.bat       打开 Windows「启动」文件夹
books\                词书（已收藏单词.csv 由程序写入，没进版本库）
fonts\Lolita.ttf      默认字体，换文件即可，族名自动读
logo\                 图标
config.json           配置，首次运行生成，删掉即恢复出厂
error.log             非致命问题的记录，出问题先看它
tests\                单元测试
tools\                词书体检 / 读音抓取与格式归一
audio\                单词读音 mp3（tools\fetch_audio.py 的产物，没进版本库）
```

启动器 `.bat` 里全是 ASCII 是故意的：`cmd` 默认按 GBK 解析 `.bat`，里面写中文会变乱码，`start` 找不到文件、`pythonw` 又没有控制台，最后失败得悄无声息。

## 开发

改完代码或者换了词书，跑这两条：

```
python -m unittest discover -s tests     # 49 条，只用标准库
python tools\check_books.py              # 扫一遍 books\ 下所有词书
```

单词读音是另外两个脚本的事，产物都在 `audio\` 下（一个词一个 mp3，文件名就是单词）：

```
python tools\fetch_audio.py        # 从有道抓读音（已有且合法的会跳过，可反复跑）
python tools\normalize_audio.py    # 把抓下来的统一成同一种 mp3 格式
```

测试盯的都是我踩过的点：词性分块（就是上面 `acquire` 那个）、释义裁剪、文案缓存的 key、配置的原子写、收藏夹 csv 往返、字体标点覆盖、GDI 位图还能不能出图、暂停用的时钟、全局热键的注册与分发、读音文件的查找（`well being` 要能捞到 `well-being.mp3`）、三个图标的布局（命中框不许互相压住、镜面圆心必须落在镜头的框里）。体检脚本会列出解析不出词性的词、义项里混进词性标记的词、重复词、缺音标、剥掉括号后没释义，以及长到读不完的文案。

> 注释里会提到 `_debug\` 下的一些标定脚本（`_stippleprobe.py`、`_hovgap.py`、`_fonttest.py`、`_capstrack.py`）—— 那些没入库。gray50 的像素占有率、0.41em 的光学修正这些数都是它们量出来的，改那些魔数之前最好先补回来。

## 已知的毛病

- 只在**主屏**飘，副屏没有
- 只在 Windows 上能跑，里面全是 win32 API
- 需要自己装 Python，没打包成 exe
- 热键是系统级注册的，运行期间占住 `Ctrl+Alt+H/P/Q`
- 注释写得比一般项目多。我是那种"参数调完三天就忘了为什么是这个值"的人，不写下来下次只能瞎试

## 数据从哪来

单词和释义来自百词斩安卓版（`com.jiongji.andriod.card`）的本地数据库，通过腾讯应用宝电脑版安卓容器 `data.vhd` 里的 ext4 `/data` 分区提取：词表在 `lookup.db → topic_book_map`，释义在 `dict_bcz`。这是本地缓存快照，云端的学习进度不在这里面。
